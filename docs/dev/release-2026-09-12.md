# Combined release verification

This release combines guarded WebMCP control, the expanded sound library and eight-track editor, built-in demo previews, playback following, extra-track colors and live meters.

Agent access is opt-in. Edits remain blocked until the user chooses the current project or saves their work and starts a new project. A subsequent ambiguous request can reopen that choice and cancel pending agent exports. Musical tool calls use revision checks and undo history. Restore before agent returns the project and session settings to the saved checkpoint and disables access.

Untouched built-in demos remain previews. Their first document edit creates an autosaved local copy. Welcome Song's composition is unchanged; Glass Arcade and After Hours demonstrate eight-track arrangements.

Release validation found a sample metadata race: the asynchronous manifest import could replace musical edits made while it loaded. A regression reproduced the lost effect before the fix. Metadata repair now checks document identity after the import and re-reads if an edit or project switch occurred. Regression tests cover both cases. The complete edit, arrange, WAV/MIDI export and reload journey passed after this fix, including export equality across reload.

## Completed checks

- TypeScript and ESLint passed.
- Full unit suite: 95 files, 1,800 tests passed. Two workers avoid a machine-load timeout in the 2,000-case codec fuzz test without reducing its cases or assertions.
- Final focused browser pack: six files, 32 tests passed, covering WebMCP, project management, sample voices, the complete edit/export/reload journey, offline network behavior and keyboard editing.
- Phone frame-budget rerun: four selected cases passed, including mobile playback/editing, lazy sample decoding and long virtualized patterns. Eight unrelated cases in that file were filtered out of this focused rerun.
- Production bundle: 97.73 KB initial JavaScript gzipped against a 300 KB budget; local WOFF2 fonts total 37.02 KB against a 50 KB budget.
- WebMCP browser tests cover destination approval, save failure, saving before creating a new project, revocation, export cancellation and restore.
- Saved-project browser journeys cover rename, delete, undo, autosave, recovery and keyboard focus. Fixtures explicitly seed saved projects now that untouched demos are previews; saved-row selectors exclude demo buttons.
- Native Chromium 151 discovered all 13 WebMCP tools and exercised tempo editing and restore at 1440x900 and 390x844. Browser flags enable the experimental API. No browser errors or horizontal overflow were observed.
- Instrument checks exercised eight-lane playback and offline export. The follow-up checks covered playback scrolling, long virtualized patterns, reduced motion, extra-track meters and persistent colors.
- Both new demos rendered finite nonzero audio below full scale. These are technical render checks, not a listening review.

## Broader browser suite

The full browser suite is not green. The previously published commit, `ed1d52e8fcc4174e380b341b626cc1a1be3a282a`, reproduced 69 failing tests and 147 passing tests in an isolated temporary checkout on this Windows Chromium runner. Its public GitHub Actions browser job also failed, while its main CI job passed: https://github.com/Arrangedgodly/DAW/actions/runs/34701754736.

An initial combined-worktree run reported 81 failures and 146 passes. Work was still arriving during that run, so it is a preflight observation, not the final immutable release result. It exposed additional outdated dropdown and saved-project assumptions, plus the metadata race fixed above. Focused reruns validate those fixes. No full-suite pass is claimed. Remaining historical checks include old layout/gesture assumptions, platform-specific screenshot paths and accessibility findings; these need a separate browser-suite repair pass.

Native WebMCP availability still depends on browser support or experimental enablement. The app does not include an origin-trial token or a hosted agent service.
