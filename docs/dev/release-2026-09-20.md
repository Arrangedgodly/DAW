# September 20 release verification

The Mixer is a separate workspace for up to eight tracks plus Master. Effects use compact horizontal cards with a contained scroll lane. Master accepts up to eight filter, drive, crush, delay or reverb devices, with add/remove/reorder/bypass controls, saved parameters and undo. Master effects run before optional output glue compression and sample-peak limiting. Playback and export use the same processing. Auto Mix analyzes locally, offers level-matched comparisons, applies one undoable edit and preserves later effects when restoring the previous mix.

This release also incorporates the current retained-overflow clip behavior, independent drum hit length and playback mode, and updated project-local WebMCP access. Tests now exercise those behaviors through their current workspaces and accessible controls.

## Local validation

- Full unit suite: 105 files, 1,885 tests passed.
- Full Chromium suite: 85 files, 263 tests executed. The run passed 260 tests and found three failures: one manual-scroll fixture and two missing Help bindings on the new focusable device rack.
- All three were repaired. A subsequent four-file run passed all 12 tests, covering the complete long-pattern benchmark file, desktop/phone Help coverage, Mixer controls, and Mixer DSP/export. Every test has passing current coverage; this was a full run followed by a focused repair run, not a second uninterrupted full run.
- The repaired 128-bar manual-scroll sweep reached the final pattern window with 100% of measured frames below 33.4 ms. The main 12-test performance group passed in the full run, including the visualizer negative control.
- ESLint, TypeScript, production build and whitespace checks passed.
- Initial JavaScript: 119.62 KiB gzip against the 300 KiB budget. WOFF2 fonts: 37.02 KiB against 50 KiB.
- Production-build Mixer smoke passed at desktop, phone and touch-tablet sizes: live metering, playback across page changes, horizontal card geometry, master effect creation, Auto Mix analysis, before/after previews, apply and restore. No page errors or horizontal document overflow. Tablet controls retained 44 px targets.
- The built-app zero-network journey passed with zero third-party calls, zero CSP violations and three real downloads. WAV, MIDI and playable video export journeys passed.

See [current testing contracts](testing-current.md) for fixture rules and performance measurements. Automated audio checks establish measured behavior; physical-device testing and a listening review are separate.

The experimental external agent router and its project-local skill setup were excluded from this release. They were removed from the local project on September 21. They were never tracked or bundled; the built-in WebMCP tools remain available.

## Hosted verification

The production deployment of app commit `955f347` passed the same Mixer smoke journey against https://bitbounce-d2d.pages.dev. Public HTML and its JavaScript returned HTTP 200; the entry asset's SHA-256 matched the local build (`f02363b6700e9633a12add77763e69185ec8ce6ddb1d3387dac11fd3ea99807b`). Cloudflare recorded the expected source commit.

The first hosted unit job exposed a codec-fuzz timeout: all 2,000 cases shared a historical six-second wall allowance, while the current corpus takes roughly five to six seconds even locally. The follow-up keeps every seed, case and safety assertion, including operation-count limits, and allows twenty seconds for this correctness corpus. The full local 1,885-test unit suite passes after that change. Hosted CI status is tracked on the repository's Actions page.

The first hosted browser run passed 254 tests and failed only the five MP4-export
checks because its Linux browser could not encode the required media. Four
trusted-touch journeys already had Linux-specific exclusions. CI now assigns
those nine tests to a dedicated macOS 15 job and the other 254 to Ubuntu,
retaining real encoded-media assertions and adding hosted coverage for the
previously excluded touch journeys.
