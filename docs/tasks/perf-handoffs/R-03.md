## Measured result

The manager granted an uncontended slot after P-04's timed work. The one browser run exited 0 in 28.65 s on headless Chromium 151.0.7922.34, Windows `win32/x64`, 1280 x 720. First Welcome Play took 94.5 ms from click to first nonempty note `postMessage`. Context resume took 37.9 ms, voice module `addModule` 16.0 ms, and mixer module `addModule` 13.2 ms. Five later Play passes across Welcome and Glass Arcade posted first note batches in 0.2 to 0.5 ms. These measure control delivery, not audible onset.

During the short eight-track visualizer window, rAF callback p95 was 5.6 ms and max 13.8 ms; the corresponding grid window was 0.4 ms p95 and 0.7 ms max. Each window had only 34 to 39 unique frame timestamps. Mixer analyser calls took 0.2 ms p95, with 14 calls in each 600 ms mixer window. One drum edit per project took 5.2 and 4.8 ms; two IDB puts followed each. This is too little edit evidence to justify a store rewrite.

Three sequential offline renders per project produced native `startRendering` medians of 1008.3 ms for Welcome and 2954.1 ms for Glass Arcade. Median render work outside `startRendering` was 80.3 and 122.6 ms. WAV encoding took 16.8 to 18.6 ms. These are offline throughput numbers, not live audio latency. Chrome reported `baseLatency` 10 ms and `outputLatency` 0 ms on its headless output device.

No physical loopback, manual listening, target phone, worklet render deadline trace, missed-note count, background timing, browser download timing, or MP4 encode/finalize timing was available. The current 120 ms foreground scheduler horizon was not changed. The development Vite server may differ from a built release startup path. See the main report for individual passes and measurement boundaries.
