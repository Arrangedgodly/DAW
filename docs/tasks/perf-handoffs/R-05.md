## Delivered and result

- [Probe](../../../tests/perf/live-event-headroom.mjs), [raw observations](../../dev/live-event-headroom-samples.json), [measurement report](../../dev/live-event-headroom.md), and focused summary/raw tests. The probe is opt-in and reads existing worklet `loaded` and `consumed` replies. It adds no audio-thread code or new worklet traffic.
- Twelve sequential foreground Play windows, six Welcome and six Glass Arcade, produced 288 posted note events in 180 batches. All 180 batches had a `loaded` reply; 180 `consumed` watermarks were observed. All mature posted events had a lane watermark after allowing for the worklet's 128-frame start-of-quantum timestamp. There were zero late posts, zero refill gaps over 120 ms, and zero page errors. Minimum main-thread send lead was 88.1 ms; the maximum refill interval was 47.4 ms. Welcome median/p95 interval was 25.0/27.0 ms and Glass Arcade was 25.0/27.2 ms.
- A separate covering-tab attempt did not make `document.hidden` true in headless Chromium. The 1.5 s hidden horizon and background timer throttling were therefore **not measured**. The raw file preserves the failed visibility observation separately.
- No scheduler horizon or other production change is supported. P-05's reverted cold-start candidate also did not improve median first-post time. A separate bounded study on a target device should capture confirmed hidden transitions, representative main-thread load, missed events, and trusted loopback or render-deadline evidence before proposing a scheduler policy change.

This ran on Windows 11 Pro 10.0.26200 x64, headless Chromium 151.0.7922.34 at 1280 x 720 using Vite dev assets. The raw file records revision, user agent, audio-clock and wall-clock timestamps, events, replies, timer callbacks, visibility state, and errors. The OS release fields were added from the same host after the capture. The probe wraps main-thread browser APIs and can add small measurement overhead. It cannot identify an event never created by the scheduler, exact worklet receipt time, worklet CPU deadline, speaker onset, or physical output latency. Offline onset tests do not close those live gaps. No manual listening or physical loopback was available.
