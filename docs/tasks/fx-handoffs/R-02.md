# R-02 handoff: Elementary benchmark diagnosis

Completed 2026-09-23. Owner scope was research only. Detailed diagnosis and P-01 contract: [`docs/dev/fx-benchmark-research.md`](../../dev/fx-benchmark-research.md).

## Completed findings

- Read repository guidance at applicable ancestor/target paths (no `AGENTS.md` found), the uncommitted benchmark TypeScript/Markdown, `src/audio/fx.ts`, installed Elementary 4.0.3 offline renderer / 4.0.1 core, and primary Elementary and Web Audio documentation.
- Confirmed the installed offline renderer copies input into native storage before processing. Its core `render()` applies a default 20 ms root fade. Short read-only probes showed sample-zero impulse lost, sample-512 impulse attenuated, and sample-1024 impulse intact. The problem is root startup attenuation, not an input delay.
- Verified the public-API repair: process 1024 block-aligned silent samples after `render`, discard that silent output, then process actual input from its sample zero. Both dry and convolve unit-IR impulses then passed. A short nontrivial IR produced identical primed vs time-shifted-fresh output over 2048 samples; previous output and input buffers remained unchanged.
- Found a second independent mismatch: production `createReverbDevice` automates gains from 1 toward wet 0.5 and dry 0.75 with 10 ms time constants; the Elementary benchmark sets those gains immediately. Separate fixed-gain convolution parity from production-device startup and settled comparisons.
- Found timing and reporting limits: native asynchronous `startRendering()` vs Elementary synchronous `process()` include different work; grouped later-beat error is unweighted and omits the tail; browser/device and live AudioWorklet behavior remain unverified.

## Evidence and limits

Read-only Node probes used installed package public APIs and a small 1- or 3-tap IR, not the browser benchmark's full seeded IR. No timed workload ran, so this work did not compete with P-02. No benchmark, production, package, branch, or other worker file was edited. The old Chrome 153 timing and 61.07% output error are cited as baseline observations, not verified performance conclusions.
