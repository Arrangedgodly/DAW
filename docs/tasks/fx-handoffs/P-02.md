## Changes

- Reverb updates compare size with the last successfully assigned size. Mix
  edits perform no IR/buffer work; changing A to B and restoring A assigns the
  appropriate buffers.
- Delay tempo sync uses the most recently accepted device parameters, so an
  edited `timeSteps` value survives tempo changes. Irrelevant device types are
  ignored.
- Added focused buffer allocation/assignment and delay sync tests, real
  Chromium OfflineAudioContext FX graph coverage, and benchmark notes in

## Measured evidence

Same deterministic seeded reverb workload in a fake Web Audio context: 24 A-B
size cycles, three mix-only edits at B, and restore to A per cycle (120 setter
calls per pass), at 44.1 kHz. Three warmup passes and nine measured passes per
version. Baseline versus fixed counts were 97 versus 49 buffer allocations and
assignments per pass. Median synchronous control-update time was 229.66 ms
(227.73–233.90 ms range) versus 95.72 ms (94.81–98.52 ms range).

These timings include seeded IR generation and fake buffer copies. They are
not audio output latency measurements. The Chromium offline render confirms
the restored reverb A output matches a fresh render and exercises actual delay
output at an edited time interval. The edit-then-tempo-sync stale-state
regression is specifically covered by the unit test.
