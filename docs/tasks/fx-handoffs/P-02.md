## Changes

- Reverb updates compare size with the last successfully assigned size. Mix
  edits perform no IR/buffer work; changing A to B and restoring A assigns the
  appropriate buffers.
- Delay tempo sync uses the most recently accepted device parameters, so an
  edited `timeSteps` value survives tempo changes. Irrelevant device types are
  ignored.
- Added focused buffer allocation/assignment and delay sync tests, real
  Chromium OfflineAudioContext FX graph coverage, and benchmark notes in
  `docs/dev/fx-control-cost.md`.
- Added a reproducible Chromium control-update benchmark. Its baseline factory
  is generated from commit `27acaec`; its fixed factory imports production
  source. The full procedure and first timing result are in
  `docs/tasks/fx-handoffs/P-02-timing-complete.md`.

## Measured evidence

Native Chromium `OfflineAudioContext` benchmark: same deterministic 24-cycle
reverb edit sequence, 120 setter calls per pass, three warmups and nine measured
passes per version in alternating order. It imported the fixed production
factory and the baseline factory generated from `27acaec`. Baseline versus
fixed counts were 97 versus 49 native buffer allocations and assignments per
pass. Median synchronous setter time was 1048 ms (987.1–1157.7 ms range) versus
465 ms (420.5–485.5 ms range).

The browser emitted all raw timings, runtime details, order, and per-step
allocation/assignment counts. Vitest then reported the completed run as timed
out at its default 15-second limit, so the run's final status is a harness
timeout after data collection. The benchmark now has a 60-second limit for
future reproductions; the heavy timed workload was not rerun. Neither this
control-update timing nor the fake-context timing above measures audio output
latency. The Chromium offline graph also confirms restored reverb A output
matches a fresh render. Delay graph coverage renders the configured 7-step
interval at 90 BPM; the unit test covers editing timeSteps before tempo sync.
