## What works

- Musical structure carries the identity. Lane colors and note lengths remain distinct against the quiet continuous material.
- Effects open within the instrument context. The empty state names the next action; the populated Filter exposes its controls without losing the lane.
- Save and export feedback is explicit. A observed RENDERING WAV followed by WAV EXPORTED and an eight-bar cycle message. This establishes visible feedback, not audio or file correctness.

## Priority issues

### P1: Lower instruments leave the compact desktop viewport

At 1280×800, A measured document height 873px. Upper panels ran from y216 to y560, and lower panels ended at y873; lower note rows and footers were below the viewport. This conflicts with DESIGN.md's explicit compact-desktop fit target. B independently found the same control-density problem at 1280×720. Scrolling works, but it breaks the intended four-instrument overview.

Budget the transport, status and instrument controls before assigning note-grid height. Reduce unnecessary vertical control space while preserving full rows and footers; use internal grid scrolling where necessary. Do not solve fit by shrinking already-small text. Inspect selected pitched lanes as well as Drums. Relevant layout rules include src/styles/membrane.css:88, :122, :173, :284 and :879, alongside inherited stage rules; these are starting points, not a diagnosed single cause. Suggested command: $impeccable layout.

### P2: Two OCT captions hide different consequences

Bass shows OCT beside its preset and again above its grid. The preset control transposes audible/exported music; the grid control only moves the view. The distinction exists in help and accessible names but not in the visible captions. A novice trying to find notes can change the music instead.

Label the sound control Transpose and the grid navigation View, retaining Oct/Semi units within that grouping. Source evidence: src/components/LaneHeader.tsx:119 and :562; src/components/LaneGrid.tsx:2009. Suggested command: $impeccable clarify.

### P2: Phone omits contextual help at the harder decisions

At 390×844 the phone interface exposes Draw/Scroll, paging and pitch navigation. The Filter uses LP, Q and BYP. App.tsx's compact path explicitly omits INFO/KEYS, so the learning support available on desktop is missing where touch gestures add complexity.

Provide a compact Help route within phone Options and short explanations for the active editing mode and device controls. Before adding recovery controls, inspect Options for existing Undo/Redo: A did not open it, and absence of a phone undo implementation was not established. Source confirms desktop keyboard undo exists. Relevant sources: src/App.tsx:147, src/components/Booth.tsx:239 and src/components/KeyboardShortcuts.tsx:138. Suggested command: $impeccable onboard.

### P2: Visible instrument categories and spoken labels disagree

Both assessors observed Keys visually while the accessibility tree still exposed LEAD, Mute LEAD and LEAD instrument preset. Users following spoken instructions and visible text have to translate between identities.

Include the same current category in visible and accessible labels while preserving a stable track identity where needed. Audit lane regions, mute/solo, preset selectors and grids together. Suggested command: $impeccable harden.

## Cognitive load and emotional journey

Hierarchy, control consequences and mobile learning support need attention. The desktop control stack precedes cramped notes; identical OCT labels impose recall; phone gesture knowledge lacks nearby explanation. Grouping and progressive disclosure already help through native preset families and in-place FX. More-than-four-option decisions include the five FX choices, 58 grouped presets, eight phone instrument tabs and Projects actions. These counts are context, not a reason to remove the sound library.

The inviting notes and direct lane switching make a strong opening. Uncertainty about view versus sound changes is the main learning valley. Explicit export completion provides a reassuring ending.
